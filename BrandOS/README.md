# OnTimer BrandOS

BrandOS is OnTimer's strategic operating system. It is the first place any AI assistant should read before creating, editing, or recommending work for OnTimer.

It is not public documentation, marketing copy, or a style guide. It is the compact source of truth for what OnTimer is, who it is for, what it promises, what language it should use, and what strategic decisions have already been made.

## Why It Exists

OnTimer strategy should not be re-litigated in every conversation. BrandOS preserves the core decisions behind the website, ASO research, product copy, competitive framing, and positioning work so future assistants can start from the same foundation.

Use BrandOS to prevent drift across:

- ASO
- Website
- Product
- Advertising
- PR
- Emails
- Screenshots
- Blog posts
- Future AI conversations

## How AI Assistants Should Use It

Before producing work for OnTimer, read these files in order:

1. `Constitution.md`
2. `Positioning.md`
3. `Customer.md`
4. `Vocabulary.md`
5. `Decision_Log.md`
6. `Current_Campaign.md`

Then use the current repository as evidence. If repo evidence conflicts with BrandOS, call out the conflict instead of silently choosing a side.

Do not expand the permanent BrandOS files casually. Version 1 should stay small, clear, and useful. Add durable strategic decisions to the core files. Put temporary active work in `Current_Campaign.md`.
